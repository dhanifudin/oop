answer: "Encapsulation"
explanation: >-
  `balance` ditandai private dan hanya diubah lewat method
  `deposit()`/`withdraw()` yang disediakan kelas ini sendiri, bukan
  diakses langsung dari luar. Ini ciri encapsulation: membundel data
  bersama method yang mengendalikan aksesnya.
---
Diberi kelas berikut:

```java
public class Wallet {
    private double balance;

    public void deposit(double amount) {
        balance += amount;
    }

    public void withdraw(double amount) {
        balance -= amount;
    }
}
```

`balance` hanya bisa berubah lewat method `deposit()` dan `withdraw()`, tidak pernah diubah langsung dari luar kelas. Pilar OOP mana yang tercermin dari desain ini?

answer: "Prosedural, karena data (nilai[]) tetap terpisah dari fungsi yang mengolahnya dan bisa diakses fungsi mana pun tanpa batasan, walau ditulis di dalam sebuah class"
explanation: >-
  Menaruh kode di dalam sebuah `class` tidak otomatis membuatnya OOP.
  Yang menentukan adalah apakah data dibundel bersama method-nya dengan
  akses dibatasi. Di sini `nilai` tetap berupa array bebas yang diproses
  method `static`, bisa dipanggil dan diutak-atik siapa saja tanpa
  batasan sama sekali, persis seperti gaya prosedural.
---
Sebuah program catatan nilai mahasiswa ditulis seperti ini:

```java
public class NilaiHelper {
    static double[] nilai = {80, 90, 75};

    static double hitungRataRata() {
        double total = 0;
        for (double n : nilai) {
            total += n;
        }
        return total / nilai.length;
    }
}
```

Kode ini ditulis di dalam sebuah `class` Java. Apakah itu cukup membuatnya bergaya OOP? Paradigma apa yang sebenarnya dipakai program ini?
